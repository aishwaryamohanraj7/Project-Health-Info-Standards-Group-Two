Task 1: Patient Extraction and Loading

In this step, patient data was extracted from the OpenEMR FHIR server using REST API calls. A specific patient (David Abshire) was retrieved using query parameters such as name and gender.

The system extracted key patient attributes including name, gender, date of birth, and address. Additionally, all associated clinical conditions were retrieved from the FHIR Condition resource.

Chronic Obstructive Pulmonary Disease (COPD) was selected as the primary condition. The SNOMED CT code 13645005 was used to represent COPD.

Parent concepts for COPD were retrieved from SNOMED CT, such as:

  • Tracheobronchial disorder
  • Chronic disease of respiratory system

The patient record was then created in the Primary Care EHR FHIR server, along with the associated parent condition.

This step represents both the Extraction and Loading phases of the ETL pipeline.

Task 2: Condition Transformation (Child Concepts)

In this step, child concepts of COPD were retrieved using SNOMED CT terminology services. These child concepts provide more specific clinical details related to the disease.

The selected child concept codes were added to the patient’s condition resource in the Primary Care EHR system.

This enhances the accuracy and granularity of clinical data representation.

This step is part of the Transformation phase, where raw data is enriched and standardized.

Task 3: Observation (Blood Pressure)

A new observation resource was created for the patient using blood pressure (BP) data.

The BP values were extracted from the OpenEMR system for the same patient (David Abshire).

The observation was structured according to the FHIR Observation resource format and added to the Primary Care EHR server.

This demonstrates the integration of clinical measurements into the ETL pipeline.

Task 4: Procedure Creation

A procedure resource was created for the patient representing a chest X-ray.

The procedure was coded using SNOMED CT standards and included details such as:

  • Procedure name: Chest X-ray
  • Status: Completed
  • Follow-up information

This ensures that clinical procedures are recorded in a standardized and interoperable format.

This step further extends the Loading phase of the ETL pipeline.

Task 5: HL7 Message Generation

In this step, an HL7 v2 message was generated using the hl7apy library.

Patient details such as name, age, and gender were included in the HL7 message. The message represents an ADT (Admit/Discharge/Transfer) event.

This demonstrates interoperability between modern FHIR-based systems and legacy HL7 messaging systems.
